Unrolled differentiation: backpropagating through the solver's iterations

After today you can differentiate the result of T solver iterations with respect to the problem's parameters by the chain rule, say what it costs in time and memory, and quantify the bias of truncating the backward pass or of using a single step.

Today's big idea

An iterative solver is a program: \(T\) applications of an update rule. Unrolled differentiation treats those \(T\) updates as \(T\) layers of a network and backpropagates through them. It is exact for the program that actually ran, it works for any differentiable solver, and it pays with memory that grows with \(T\). Truncating the backward pass trades a small, predictable bias for that memory.

1. The solver as a chain of maps

Start from an initial guess \(\mathbf{x}_0 = \Phi_0(\mathbf{y})\) and apply an update map \(T\) times: §4.2.1 · pp. 104–105

\[ \mathbf{x}_t = \Phi_t(\mathbf{x}_{t-1};\, \mathbf{y}), \qquad t = 1, \dots, T . \tag{4.4} \]

The book's example of an update map is one step of gradient descent on the lower-level cost, with learning rate \(\eta_t\):

\[ \Phi_t(\mathbf{x}_{t-1};\, \mathbf{y}) = \mathbf{x}_{t-1} - \eta_t\, \frac{\partial \mathcal{L}(\mathbf{x}_{t-1}, \mathbf{y})}{\partial \mathbf{x}_{t-1}} . \tag{4.5} \]

A Gauss-Newton or Levenberg-Marquardt step is another valid \(\Phi_t\) (footnote 1, p. 105). Stop after \(T\) steps and use \(\mathbf{x}_T\) in place of the true minimizer:

\[ \mathbf{x}^* \approx \mathbf{x}_T = \Phi(\mathbf{y}) = (\Phi_T \circ \cdots \circ \Phi_1 \circ \Phi_0)(\mathbf{y}) . \tag{4.6} \]

The bilevel problem (4.2) then collapses into an ordinary single-level problem, \(\min_{\mathbf{y}} \mathcal{U}(\mathbf{y}, \Phi(\mathbf{y}))\), equation (4.7), in which \(\Phi\) is just a deep function of \(\mathbf{y}\). AutoDiff can differentiate it. §4.2.1 · p. 105

2. The chain rule along the chain

The book stops at "compute \(\partial\Phi(\mathbf{y})/\partial\mathbf{y}\) via AutoDiff". It is worth seeing what AutoDiff actually computes, because the formula explains the cost.

Filling the gap: the sensitivity recursion

Differentiate (4.4) with respect to \(\mathbf{y}\). \(\Phi_t\) depends on \(\mathbf{y}\) in two ways: directly, and through \(\mathbf{x}_{t-1}\). Name the two partial derivatives

\[ \mathbf{A}_t = \frac{\partial \Phi_t}{\partial \mathbf{x}_{t-1}} \;(n\times n), \qquad \mathbf{B}_t = \frac{\partial \Phi_t}{\partial \mathbf{y}} \;(n\times m), \]

and the quantity we are after \(\mathbf{S}_t = \partial\mathbf{x}_t/\partial\mathbf{y}\). Then

\[ \mathbf{S}_t = \mathbf{A}_t\,\mathbf{S}_{t-1} + \mathbf{B}_t, \qquad \mathbf{S}_0 = \frac{\partial\Phi_0}{\partial\mathbf{y}} \quad(\text{zero if the initial guess ignores } \mathbf{y}). \]

Running this next to the solver is forward mode. For the gradient-descent map (4.5), differentiating once more gives

\[ \mathbf{A}_t = \mathbf{I} - \eta_t\,\frac{\partial^2\mathcal{L}}{\partial\mathbf{x}\,\partial\mathbf{x}}, \qquad \mathbf{B}_t = -\eta_t\,\frac{\partial^2\mathcal{L}}{\partial\mathbf{x}\,\partial\mathbf{y}}, \qquad \text{both at } (\mathbf{x}_{t-1}, \mathbf{y}). \]

Unfolding the recursion shows the "sum over paths":

\[ \mathbf{S}_T = \mathbf{B}_T + \mathbf{A}_T\mathbf{B}_{T-1} + \mathbf{A}_T\mathbf{A}_{T-1}\mathbf{B}_{T-2} + \dots + \mathbf{A}_T\cdots\mathbf{A}_2\mathbf{B}_1 \;(+\; \mathbf{A}_T\cdots\mathbf{A}_1\mathbf{S}_0). \]

Reverse mode computes the same sum from the other end, without ever forming an \(n\times m\) matrix. Start with the adjoint \(\boldsymbol{\lambda}_T = (\partial\mathcal{U}/\partial\mathbf{x}_T)\T\) and walk back:

\[ \boldsymbol{\lambda}_{t-1} = \mathbf{A}_t\T\,\boldsymbol{\lambda}_t, \qquad \nabla_{\mathbf{y}}\,\mathcal{U} = \frac{\partial\mathcal{U}}{\partial\mathbf{y}} + \sum_{t=1}^{T} \boldsymbol{\lambda}_t\T\,\mathbf{B}_t . \]

Each backward step needs \(\mathbf{A}_t\) and \(\mathbf{B}_t\), which are evaluated at \(\mathbf{x}_{t-1}\). That is why every iterate must still be in memory when the backward pass reaches it.

Worked example. The toy problem of Day 1: \(\mathcal{L} = \tfrac12(x^2-y)^2 + \tfrac12(x-1)^2\), with \(\partial\mathcal{L}/\partial x = 2x(x^2-y) + (x-1)\), \(\partial^2\mathcal{L}/\partial x^2 = 6x^2 - 2y + 1\), and \(\partial^2\mathcal{L}/\partial x\,\partial y = -2x\). So \(A_t = 1 - \eta(6x_{t-1}^2 - 2y + 1)\) and \(B_t = 2\eta\,x_{t-1}\). Take \(y = 2\), \(x_0 = 1\), \(\eta = 0.1\):

After two steps, forward mode gives \(\nabla_y\,\mathcal{U} = (x_2 - 1.5)\,S_2 = (-0.1856)(0.3272) = -0.0607\). Reverse mode on the same two steps: \(\lambda_2 = -0.1856\), \(\lambda_1 = A_2\lambda_2 = -0.0809\), and \(\lambda_2 B_2 + \lambda_1 B_1 = -0.0445 - 0.0162 = -0.0607\). Same number, as it must be. The true gradient from Day 1 is \(-0.0447\); with only two steps we are differentiating a solver that has not converged yet.

3. Exact for the program, not for the problem

Try it: the chart plots each estimate of dU/dy against the number of inner steps K. Raise K, then switch the inner solver to Gauss-Newton.

Notice that at the defaults (gradient descent, η = 0.1, K = 2) the unrolled gradient is −0.0607, the value from the worked example, while the reference is −0.0447. By K = 8 they agree. Lower η to 0.05 and it takes about K = 20; switch to Gauss-Newton and K = 2 is enough. The unrolled gradient is always the exact derivative of U(x_K), and it is only as good as x_K is close to x*.

The costs follow directly from the recursions: §4.2.1–4.2.2 · pp. 105–106

With \(m\) in the millions, forward mode is out. Reverse mode it is, and then memory grows linearly with \(T\). The book calls this the difficulty of "long-term dependencies", and it gets worse when both \(\mathbf{x}\) and \(\mathbf{y}\) are high-dimensional. §4.2.2 · p. 106

Intuition

Reverse-mode unrolling is like auditing a calculation by replaying the tape backward. You can do it only if you kept the whole tape. A solver that needs 100 iterations produces a tape 100 states long, even though only the last state is the answer.

4. Truncated unrolling: keep only the last M steps

Truncated unrolled differentiation stops the backward walk after \(M\) steps: it uses \(t = T, T-1, \dots\) and ignores the influence that \(\mathbf{y}\) had on earlier iterates. Only the last \(M\) iterates are stored. The book reports (citing its reference [992]) that a few backward steps can perform comparably to the exact gradient with much less memory and computation. §4.2.2 · p. 106

Filling the gap: how big is the truncation bias?

Truncation keeps the first \(M\) terms of the sum for \(\mathbf{S}_T\) above and drops the rest. Every dropped term contains at least \(M\) factors \(\mathbf{A}\). Near the solution the iterates barely change, so \(\mathbf{A}_t \approx \mathbf{A}\) and \(\mathbf{B}_t \approx \mathbf{B}\) are nearly constant, and for a solver that converges, repeated multiplication by \(\mathbf{A}\) shrinks vectors (that is what convergence means). In the scalar toy problem this is a geometric series:

\[ S_{\text{full}} = B\,(1 + A + A^2 + \dots) = \frac{B}{1-A}, \qquad S_{\text{last } M} = B\,(1 + A + \dots + A^{M-1}) = \frac{B\,(1 - A^M)}{1-A} . \]

The truncated gradient is the full one times \(1 - A^M\): the fraction \(A^M\) is missing. For gradient descent with \(\eta = 0.1\) at the solution \(x^* = 1.366\), \(A = 1 - 0.1\times 8.196 = 0.18\). So \(M = 1\) loses 18%, \(M = 2\) loses 3.2%, \(M = 3\) loses 0.6%. In the widget set K = 30 and "Backprop through last M" to 1: the truncated gradient reads −0.0366, which is 82% of −0.0447.

The rule to remember: the slower the inner solver converges (the closer \(A\) is to 1), the more backward steps you need. A second-order solver such as Gauss-Newton has a small \(A\) near the solution, so short truncation works well with it.

5. The extreme case: one inner step

Under tight memory and time limits, some methods unroll a single step, \(\mathbf{x}_1(\mathbf{y}) = \Phi_1(\mathbf{x}_0;\mathbf{y})\), and use §4.2.2 · p. 106

\[ \nabla_{\mathbf{y}}\,\mathcal{U} = \frac{\partial\,\mathcal{U}(\mathbf{y},\mathbf{x}_1(\mathbf{y}))}{\partial\mathbf{y}} + \frac{\partial\,\mathcal{U}(\mathbf{y},\mathbf{x}_1(\mathbf{y}))}{\partial\mathbf{x}_1}\,\frac{\partial\mathbf{x}_1(\mathbf{y})}{\partial\mathbf{y}}, \tag{4.8} \] \[ \frac{\partial\mathbf{x}_1(\mathbf{y})}{\partial\mathbf{y}} = -\frac{\partial^2\mathcal{L}(\mathbf{x}_0,\mathbf{y})}{\partial\mathbf{x}_0\,\partial\mathbf{y}} . \tag{4.9} \]

Equation (4.9) is \(\mathbf{B}_1\) from §2 for a gradient step with the learning rate set to 1; with a general learning rate it is \(-\eta\,\partial^2\mathcal{L}/\partial\mathbf{x}_0\partial\mathbf{y}\). The matrix of mixed second derivatives is \(n\times m\) and expensive, but (4.8) needs only its product with the row vector \(\partial\mathcal{U}/\partial\mathbf{x}_1\).

Filling the gap: where the finite difference (4.10) comes from

Let \(\mathbf{v} = (\partial\mathcal{U}/\partial\mathbf{x}_1)\T\). We want \(\mathbf{v}\T\,\dfrac{\partial^2\mathcal{L}}{\partial\mathbf{x}\,\partial\mathbf{y}}\). Its transpose is \(\dfrac{\partial^2\mathcal{L}}{\partial\mathbf{y}\,\partial\mathbf{x}}\,\mathbf{v}\), and that is a directional derivative: the rate at which the gradient \(\partial\mathcal{L}/\partial\mathbf{y}\) changes when \(\mathbf{x}\) moves along \(\mathbf{v}\). A central difference estimates it from two gradient evaluations at \(\mathbf{x}_0^{\pm} = \mathbf{x}_0 \pm \epsilon\,\mathbf{v}\):

\[ \frac{\partial^2\mathcal{L}}{\partial\mathbf{y}\,\partial\mathbf{x}}\,\mathbf{v} \;\approx\; \frac{1}{2\epsilon}\left( \frac{\partial\mathcal{L}(\mathbf{x}_0^{+},\mathbf{y})}{\partial\mathbf{y}} - \frac{\partial\mathcal{L}(\mathbf{x}_0^{-},\mathbf{y})}{\partial\mathbf{y}} \right) . \]

This is the right-hand side of the book's (4.10). To get the second term of (4.8), multiply by the factor from (4.9): \(-1\), or \(-\eta\) for a general learning rate. Keep track of that sign when you implement it.

Toy check with \(x_0 = 1\), \(y = 2\), \(\eta = 0.1\): \(x_1 = 1.2\), so \(v = x_1 - 1.5 = -0.3\). Here \(\partial\mathcal{L}/\partial y = y - x^2\). With \(\epsilon = 0.01\): \(x_0^{+} = 0.997\), \(x_0^{-} = 1.003\), and

\[ \frac{(2 - 0.997^2) - (2 - 1.003^2)}{0.02} = \frac{1.005991 - 0.993991}{0.02} = 0.6 . \]

Exact value: \((-2x_0)\,v = (-2)(-0.3) = 0.6\). The gradient term is \(-\eta\times 0.6 = -0.06\), which is what the widget shows at K = 1.

One caution from the book: the perturbation \(\mathbf{x}_0 \pm \epsilon\,\mathbf{v}\) is a plain addition only for vector variables. If \(\mathbf{x}\) contains rotations or poses, the perturbation must be applied on the manifold, which is the subject of Day 4. §4.2.2 · p. 106

Common mistakes

  • "Unrolling gives the gradient of the bilevel problem." It gives the gradient of \(\mathcal{U}(\mathbf{x}_T)\). The two agree only when \(\mathbf{x}_T\) has converged.
  • "More inner steps always cost more memory." Only in reverse mode without truncation. With truncation the memory is set by \(M\), not \(T\).
  • "If the initial guess is good, no gradient is lost." With zero inner steps, \(\mathbf{x}_0\) does not depend on \(\mathbf{y}\) at all (unless the initializer does) and the indirect gradient is exactly zero, however good the guess.

Check yourself

Q1. Toy problem, gradient descent with η = 0.1 from x₀ = 1 at y = 2. The initial guess does not depend on y. What is dx₁/dy?

S₁ = B₁ = −η · ∂²L/∂x∂y = −0.1 · (−2 · 1) = 0.2. The value 0.333 is the converged sensitivity; 0.4 is what one Gauss-Newton step gives.

Q2. You unroll T = 200 solver iterations in reverse mode. Each iterate has n = 500,000 numbers stored as 8-byte floats. How much memory do the stored iterates alone need?

200 × 500,000 × 8 bytes = 800,000,000 bytes = 800 MB. One iterate is only 4 MB; the factor T is the cost of unrolling.

Q3. Near the solution, each backward step multiplies the adjoint by A = 0.5. If you truncate the backward pass to the last M = 3 steps, what fraction of the converged gradient is missing?

The truncated sum is (1 − A^M) of the full one, so the missing fraction is A^M = 0.5³ = 0.125.

Q4. In the widget at η = 0.1 and K = 2 the unrolled gradient is −0.0607 but the finite-difference reference is −0.0447. What explains the gap?

Unrolling differentiates the program that ran. Two steps of gradient descent define a different function of y than the converged solution does. Forward and reverse mode give the same −0.0607.

Q5. One-step approximation with learning rate η = 0.1. The central difference of ∂L/∂y along v = ∂U/∂x₁ returns 0.6. What is the second term of (4.8)?

The finite difference estimates (∂²L/∂y∂x)·v. The term in (4.8) multiplies it by ∂x₁/∂y's factor −η from (4.9): −0.1 × 0.6 = −0.06.

Recap

  1. Unrolling writes the solver as \(\mathbf{x}_T = (\Phi_T\circ\dots\circ\Phi_0)(\mathbf{y})\) and differentiates that composition with AutoDiff.
  2. The sensitivity obeys \(\mathbf{S}_t = \mathbf{A}_t\mathbf{S}_{t-1} + \mathbf{B}_t\); reverse mode evaluates the same sum backward with adjoints \(\boldsymbol{\lambda}_{t-1} = \mathbf{A}_t\T\boldsymbol{\lambda}_t\) and must store all iterates.
  3. The result is exact for \(\mathbf{x}_T\) and approaches the true bilevel gradient as the inner solver converges.
  4. Truncating to the last \(M\) steps drops terms of size about \(A^M\); fast inner solvers tolerate short truncation.
  5. The one-step version (4.8)–(4.10) needs only two extra gradient evaluations, at the price of a large bias when one step is far from solving the lower level.
