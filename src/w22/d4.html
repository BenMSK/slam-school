Dense semantic maps: fusing labels into surfels and voxels

After today you can explain how noisy per-frame labels are fused into surfel and voxel maps, derive the multi-class log-odds update, and run it by hand for one voxel.

Today's big idea

A dense semantic map keeps, for every small piece of space, a probability for each class. One segmented image is noisy, so the map fuses many with Bayes' rule. Written in log-odds, that fusion is an addition: each observation adds a fixed vector to the cell it touches.

1. Labels on points and surfels

Segmentation networks can label every point of a LiDAR scan. The labels of one scan are noisy and disagree with the next scan's, so the mapping problem is to integrate them over time. SuMa++ stores a class and a confidence in each surfel. Conflicting labels lower the confidence, and surfels with low confidence are filtered out. §16.3.1 · p. 471

The same mechanism handles moving objects. Deleting every point of a movable class throws away parked cars, which are good references for scan registration in a city. Deleting only the surfels whose stored label conflicts with the current scan worked better. §16.3.1 · p. 472

Labels also feed back into SLAM: registration can match only points of compatible classes (compare ICP in Week 13 · Day 2), and place descriptors such as Scan Context (Week 13 · Day 4) can be extended with class information for loop closure. §16.3.1 · p. 472

2. Voxels: what is observed and what is estimated

Split the environment into classes \(\mathcal{K} = \{0, \dots, K\}\), where 0 is free space and the others are object classes. A range-category observation is, for each sensor ray \(b\), a pair \(z = (r_{t,b}, y_{t,b})\): the range at which the ray stopped and the class of what it hit. An RGB-D camera produces one per pixel by pairing the depth image with a segmentation of the colour image. §16.3.2 · p. 473

The map \(\mathbf{m}\) is a grid of cells \(i = 1, \dots, N\), each with an unknown class \(m_i \in \mathcal{K}\). With the robot poses known, Bayes' rule updates the map's probability mass function \(p_t(\mathbf{m})\) with each new observation set \(\mathcal{Z}_{t+1}\):

\[ p_{t+1}(\mathbf{m}) \propto p(\mathcal{Z}_{t+1} \mid \mathbf{m})\, p_t(\mathbf{m}), \qquad p_t(\mathbf{m}) = \prod_{i=1}^{N} p_t(m_i). \tag{16.23} \]

The second equation is an approximation chosen for cost: cells are treated as independent, so the map stores \(N\) small distributions and not one distribution over \((K+1)^N\) maps. §16.3.2 · pp. 473–474

3. Multi-class log-odds

Each cell stores its distribution as a multi-class log-odds vector, the log of each class probability relative to "free": §16.3.2 · p. 474

\[ \mathbf{h}_{t,i} = \begin{bmatrix} \log\frac{p_t(m_i=0)}{p_t(m_i=0)} & \cdots & \log\frac{p_t(m_i=K)}{p_t(m_i=0)} \end{bmatrix}\T \in \R^{K+1}, \qquad p_t(m_i = k) = \frac{e^{h_k}}{\sum_{j=0}^{K} e^{h_j}} . \]

The first entry is always 0. The second formula, the softmax, recovers the probabilities. In these coordinates the Bayesian update is a sum:

\[ \mathbf{h}_{t+1,i} = \mathbf{h}_{t,i} + \sum_{z \in \mathcal{Z}_{t+1}} \mathbf{l}_i(z), \qquad \mathbf{l}_i(z) = \begin{bmatrix} \log\frac{p(z \mid m_i=0)}{p(z \mid m_i=0)} & \cdots & \log\frac{p(z \mid m_i=K)}{p(z \mid m_i=0)} \end{bmatrix}\T . \tag{16.24, 16.25} \]

Filling the gap: deriving (16.24) and the softmax

Bayes' rule for one cell and one observation, with \(\eta\) a normalizer that does not depend on \(k\):

\[ p_{t+1}(m_i = k) = \eta\; p(z \mid m_i = k)\; p_t(m_i = k). \]

Write the same line for \(k = 0\), divide, and take logarithms. \(\eta\) cancels:

\[ \underbrace{\log\frac{p_{t+1}(m_i=k)}{p_{t+1}(m_i=0)}}_{\text{entry } k \text{ of } \mathbf{h}_{t+1,i}} = \underbrace{\log\frac{p(z \mid m_i=k)}{p(z \mid m_i=0)}}_{\text{entry } k \text{ of } \mathbf{l}_i(z)} + \underbrace{\log\frac{p_t(m_i=k)}{p_t(m_i=0)}}_{\text{entry } k \text{ of } \mathbf{h}_{t,i}} . \]

If the observations are independent given the cell's class, their likelihoods multiply and their logs add, which gives the sum over \(z\). For the softmax, \(h_k = \log[p(k)/p(0)]\) means \(p(k) = p(0)\,e^{h_k}\). The probabilities sum to one, so \(p(0)\sum_j e^{h_j} = 1\), and substituting \(p(0)\) back gives the formula. With \(K = 1\) the vector is \([0,\ \log(p_{\text{occ}}/p_{\text{free}})]\): the occupancy log-odds of Week 8 · Day 1.

4. The observation model, with numbers

A ray says three different things to three kinds of cell, and the book's model is piecewise constant along the ray: §16.3.2 · p. 475

\[ \mathbf{l}_i((r, y)) = \begin{cases} \boldsymbol{\phi}^+ + \mathbf{E}_{y+1}\boldsymbol{\psi}^+, & r \text{ indicates } m_i \text{ is occupied},\\ \boldsymbol{\phi}^-, & r \text{ indicates } m_i \text{ is free},\\ \mathbf{0}, & \text{otherwise}. \end{cases} \tag{16.26} \]

\(\mathbf{E}_k = \mathbf{e}_k\mathbf{e}_k\T\) keeps only entry \(k\) of a vector, and the first entries of \(\boldsymbol{\phi}^+, \boldsymbol{\psi}^+, \boldsymbol{\phi}^-\) are 0. So a hit raises every object class against "free" (\(\boldsymbol{\phi}^+\)) and raises the reported class \(y\) a little more (\(\boldsymbol{\psi}^+\)); a pass-through lowers every object class (\(\boldsymbol{\phi}^-\) has negative entries).

Filling the gap: where the parameter vectors come from, and three updates by hand

The entries are log likelihood ratios, as (16.25) says. Take classes {free, chair, table} and this sensor: a ray passes through a free cell with probability 0.9 and reports a false hit of either class with probability 0.05 each; it passes through an occupied cell without stopping with probability 0.2, and when it stops the label is right with probability 0.75, so a chair cell gives "hit, chair" with probability 0.6 and "hit, table" with 0.2. Then

\[ \mathbf{l}(\text{hit, chair}) = \begin{bmatrix} 0 & \ln\frac{0.6}{0.05} & \ln\frac{0.2}{0.05} \end{bmatrix} = [0,\ 2.48,\ 1.39], \qquad \mathbf{l}(\text{pass}) = \begin{bmatrix} 0 & \ln\frac{0.2}{0.9} & \ln\frac{0.2}{0.9} \end{bmatrix} = [0,\ -1.50,\ -1.50], \]

which is (16.26) with \(\boldsymbol{\phi}^+ = [0, 1.39, 1.39]\), \(\boldsymbol{\psi}^+ = [0, 1.10, 1.10]\), \(\boldsymbol{\phi}^- = [0, -1.50, -1.50]\). Start a cell at \(\mathbf{h} = [0, 0, 0]\) (all classes equally likely) and fuse three hits labelled chair, table, chair:

\[ \mathbf{h} = [0,\ 2.48 + 1.39 + 2.48,\ 1.39 + 2.48 + 1.39] = [0,\ 6.36,\ 5.26], \qquad e^{\mathbf{h}} = [1,\ 576,\ 192]. \]

The softmax gives \(p = [1, 576, 192]/769 = [0.001,\ 0.749,\ 0.250]\). The cell is almost surely occupied, and chair leads table three to one: two votes against one, each worth a factor \(0.6/0.2 = 3\).

Try it: press "Sample 1" once. Reset and press "Sample 10". Then set the label accuracy to 50% and sample again.

Notice that one hit already gives chair 71%, table 24%, free 6%. Ten samples (eight labelled chair, one labelled table, one pass-through) put chair at 99.95%. At 50% accuracy the labels carry no information: chair and table stay tied, yet "free" is still ruled out, because that part of the evidence comes from the range.

5. Storing it: the multi-class octree

A regular grid wastes memory on large empty volumes. An octree (Week 8 · Day 4) divides space recursively into eight octants; a node has either 8 children or none, and a node without children is a leaf. In a multi-class octree every node stores a log-odds vector. §16.3.2 · pp. 475–476

  • Update. Cast the ray through the tree, expand each observed leaf down to the finest resolution, and apply (16.24).
  • Prune. If the 8 children of a node are leaves with equal log-odds, delete them and make the parent a leaf. A free block of \(16^3 = 4096\) finest cells collapses to one node. Occupied regions rarely prune, since only their surfaces are observed.
  • Clamp. Noise keeps equal cells from reaching exactly equal values. Limiting each entry of \(\mathbf{h}\) to a fixed interval lets cells settle at the same value and prune, at the price of losing information near certainty.
  • Keep few classes. Cost grows linearly with \(K\) and the chance of pruning falls quickly, so a cell may store only its \(\bar{K}\) most likely classes and lump the rest into "others".

A parent's vector can be the average of its children's, or, conservatively, that of the child most likely to be occupied. Several robots can build one such map by agreeing on their local octrees over one-hop communication (ROAM). §16.3.2 · pp. 476–478

Check yourself

Q1. With classes {free, 1, 2}, a cell has h = [0, 1.1, −0.7]. What is the probability of class 1?

e^0 = 1, e^1.1 = 3.00, e^−0.7 = 0.50. Softmax: 3.00/(1 + 3.00 + 0.50) = 0.67.

Q2. A sensor reports "hit, class 1" with probability 0.6 if the cell is class 1, 0.1 if it is class 2, and 0.02 if it is free. What does this observation add to the class-2 entry of h?

Entry 2 of l(z) is ln[p(z | class 2)/p(z | free)] = ln(0.1/0.02) = ln 5 = 1.61. Even a hit with the other label is evidence that the cell is not free.

Q3. In a city, which rule for handling movable objects in a semantic surfel map worked better according to the chapter?

Parked vehicles are common and useful for registration. Removing all of them discards good constraints, so only surfels with conflicting labels are filtered.

Q4. Why does free space compress much better than occupied space in a multi-class octree?

Pruning needs 8 equal children. Rays cross free volumes everywhere and clamping makes their values equal. The inside of an object is never observed, so its cells differ from the surface cells.

Recap

  1. Surfel maps keep a class and a confidence per surfel; conflicting labels lower the confidence.
  2. A range-category observation gives a range and a class per ray. The voxel map keeps an independent class distribution per cell.
  3. In log-odds relative to "free", Bayes' rule is \(\mathbf{h} \leftarrow \mathbf{h} + \mathbf{l}(z)\), and the softmax returns probabilities.
  4. The model (16.26) adds \(\boldsymbol{\phi}^+ + \mathbf{E}_{y+1}\boldsymbol{\psi}^+\) at the ray's end point and \(\boldsymbol{\phi}^-\) along the way. The entries are log likelihood ratios of the sensor.
  5. A multi-class octree prunes equal children; clamping and keeping few classes make pruning likely.
