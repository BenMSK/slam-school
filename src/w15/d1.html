How an event camera works

After today you can state the event generation model, predict how many events a brightness change produces, and explain where the sensor's speed and dynamic range come from.

Today's big idea

A standard camera asks every pixel "how bright are you?" at fixed times. An event camera lets every pixel speak for itself, and only when its brightness has changed by a set amount. The output is a stream of events, each saying "pixel \(\mathbf{x}\) got brighter (or darker) at time \(t\)". One short equation, (10.1), describes the whole sensor.

1. A pixel that reports only change

The cameras of Week 11 · Day 3 expose all pixels together and deliver a full image at a rate set by a clock, for example 30 Hz. Between two frames they see nothing, and if nothing moves they send the same picture again. Ch. 10 intro · p. 282

The pixels of an event camera, such as the Dynamic Vision Sensor (DVS), work independently of each other. Each one watches its own log intensity \(L = \log I\), where \(I\) is the light falling on it. It memorizes \(L\) at the moment it last sent an event and keeps comparing the current value with that memory. When the difference reaches the contrast threshold \(C\), the pixel sends a new event and memorizes the new level: §10.1.1 · p. 283

\[ \Delta L \doteq L(\mathbf{x}_k, t_k) - L(\mathbf{x}_k, t_k - \Delta t_k) = p_k\, C . \tag{10.1} \]

The event is the triple \(e_k \doteq (\mathbf{x}_k, t_k, p_k)\): the pixel location \(\mathbf{x}_k\), the time \(t_k\), and the one-bit polarity \(p_k \in \{+1, -1\}\), which says whether the brightness went up (an ON event) or down (an OFF event). \(\Delta t_k\) is the time since the previous event at the same pixel. Equation (10.1) is called the event generation model.

A worked example with \(C = 0.2\). A pixel has just fired, and the light on it then rises from 40 to 100 units. The log intensity rises by \(\ln(100/40) = \ln 2.5 = 0.916\). That is \(0.916 / 0.2 = 4.58\) thresholds, so the pixel fires 4 ON events and is left \(0.116\) above its last memorized level. If the light now falls to 50 units, \(L\) sits at \(\ln(50/40) = 0.223\) above the start, which is \(0.8 - 0.223 = 0.577\) below the memory: 2 OFF events. In general, a pixel that has just fired and then sees a change \(\Delta L\) in one direction sends

\[ n = \left\lfloor \frac{|\Delta L|}{C} \right\rfloor \ \text{events.} \]

The book does not fix the base of the logarithm. This course uses the natural logarithm; another base only rescales \(C\).

Filling the gap: why the logarithm?

The book says each event is a change of "logarithmic intensity" and leaves it there. Three consequences follow from one identity, \(\log a - \log b = \log(a/b)\).

The threshold is a ratio. \(\Delta L = \log I_\text{new} - \log I_\text{old} = \log (I_\text{new}/I_\text{old})\). An ON event with \(C = 0.3\) means the light grew by the factor \(e^{0.3} = 1.35\), that is by 35%. An OFF event means it shrank by the factor \(e^{-0.3} = 0.74\). The same 35% step triggers an event in moonlight and in sunlight.

The lighting level cancels. Model the light reaching a pixel as illumination times surface reflectance, \(I = E\,\rho\). Then \(L = \log E + \log \rho\). If the lamp is made 100 times brighter, every \(L\) shifts by the same constant \(\log 100\), and every difference \(\Delta L\) stays what it was. The events do not change. You will test this in the widget below.

Dynamic range in decibels. The dynamic range of an image sensor is the ratio of the brightest to the darkest light it can register, quoted as \(20 \log_{10}(I_{\max} / I_{\min})\) decibels (dB). The book's figures §10.1.2 · p. 285 translate to

\[ 60\ \text{dB} \Rightarrow \frac{I_{\max}}{I_{\min}} = 10^{3}, \qquad 120\ \text{dB} \Rightarrow \frac{I_{\max}}{I_{\min}} = 10^{6}. \]

So "more than 120 dB against 60 dB" means the usable brightness ratio is at least a thousand times larger. The book gives two reasons: each pixel works on its own, with no exposure setting shared by the whole image, and each pixel converts light to voltage on a logarithmic scale.

2. Events against frames

Event cameras are data-driven: how much they output depends on how much the scene changes. Faster motion gives more events per second, because each pixel samples its signal at the rate the signal changes. §10.1.1 · pp. 283–284

Try it: a bright bar crosses a row of 60 pixels. Change the speed, then the threshold, then the scene light.

Notice four things. At the start there are 593 events, 7 per pixel for each edge that passes, because \(\lfloor \ln 10 / 0.30 \rfloor = 7\). Raising the speed does not change that 7; it squeezes the same events into less time, so the rate goes up. The frame camera smears the bar over speed × exposure (7.5 px) and misses everything between frames (16.7 px of travel). And with the light 100 times dimmer or brighter the events are identical, while the frame keeps 3 or 0 grey levels of contrast out of 229.

In plain words

A frame camera is a class photo taken every so often: everyone is in it whether they moved or not. An event camera is a room where each person calls out only when something changes for them. A quiet room tells you nothing moved. A burst of calls tells you where and exactly when.

The book lists four advantages. Each follows from "independent pixels that report log changes". §10.1.2 · p. 285

The DVS pixel has three stages that turn light into a voltage, subtract the memorized level, and compare the difference with the threshold. The book relates them to three layers of the retina (Figure 10.2). Some sensors, the ATIS and the DAVIS, also output ordinary grayscale images from the same chip. §10.1.1 · p. 284

4. Which camera for SLAM?

The book notes four trends in commercial devices. §10.1.3 · pp. 285–286

  • Smaller pixels. The pixel pitch fell from 40 µm in the DVS128 to under 5 µm. An event pixel needs more transistors than an ordinary one, so stacked chips and backside illumination are used to keep enough light-sensitive area.
  • Grayscale output is disappearing. Newer high-definition models dropped it to leave room for the event circuit.
  • Colour is rare. Motion tasks seldom need it.
  • A built-in IMU is common. It allows visual-inertial odometry, the subject of Weeks 16 and 17.

More pixels are not automatically better. A one-megapixel event camera moving fast over a textured scene can emit hundreds of millions of events per second. That can saturate the camera's output bus, and according to the book no current algorithm and hardware pair processes such a rate in real time without first converting the events to arrays or dropping some. For prototyping and for robots with little computing power, the book recommends a lower resolution such as QVGA, and adds that the choice of lens (field of view) often matters as much as the pixel count. §10.1.3 · p. 286

Common mistakes

  • "An event tells you how bright the pixel is." It tells you only that the log brightness moved by \(C\) since the last event, and in which direction. Absolute brightness is not transmitted.
  • "The number of events from an edge depends on how fast it moves." In the ideal model the count per pixel depends on the brightness ratio and on \(C\). Speed sets how close together in time they arrive.
  • "A still camera in a still scene sends a steady stream." With constant lighting it sends nothing except noise. Events need motion or changing light. §10.1.1 · p. 283

Check yourself

Q1. A pixel has just fired. The light on it then triples. With C = 0.25 (natural log), how many ON events does the ideal pixel send?

ΔL = ln 3 = 1.099, and 1.099 / 0.25 = 4.39, so 4 events fire. The remaining 0.099 stays below the threshold.

Q2. The same edge crosses the same pixel twice as fast. In the ideal model, what changes?

The count is set by the total change in log brightness divided by C. The speed only compresses the timestamps, which doubles the event rate.

Q3. A scene is filmed twice with the same camera motion, once under a lamp and once under a lamp ten times brighter. How do the ideal event streams compare?

Ten times more light adds the constant log 10 to every L. Events depend only on differences of L, and the constant cancels.

Q4. A sensor with 120 dB of dynamic range is compared with one of 60 dB. By what factor is its ratio of brightest to darkest usable light larger?

With 20 log₁₀ of the ratio, 120 dB is a ratio of 10⁶ and 60 dB is 10³. The ratio of the two is 10³ = 1000.

Recap

  1. Each pixel memorizes its log intensity at its last event and fires again when the current value differs from it by the contrast threshold \(C\): equation (10.1).
  2. An event is (pixel, time, polarity). It carries the sign of a change, not a brightness.
  3. A change \(\Delta L\) produces \(\lfloor |\Delta L| / C \rfloor\) events. Faster motion gives the same events sooner, so a higher rate.
  4. Because \(L\) is a logarithm, the threshold is a brightness ratio and the lighting level cancels. That, with independent pixels, gives the high dynamic range.
  5. For SLAM, a moderate resolution is often the practical choice: megapixel sensors can produce more events than can be transmitted or processed.
