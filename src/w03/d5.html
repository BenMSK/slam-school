iSAM and iSAM2: incremental smoothing and mapping

After today you can describe how iSAM1 and iSAM2 keep a SLAM solution up to date, including incremental reordering, partial back-substitution and selective relinearization, and say when an update is cheap and when it is not.

Today's big idea

Incremental smoothing and mapping keeps the whole trajectory in the estimate but does only the work a new measurement calls for. iSAM1 updates the matrix \(\mathbf{R}\) directly and starts over from time to time. iSAM2 edits the Bayes tree and is lazy in three places: it reorders only the variables it re-eliminates, re-solves only where the answer moved, and relinearizes only the factors whose variables moved.

1. iSAM1: add a row to R without refactoring

The first version, iSAM1, used the incremental matrix factorization methods of Golub and Van Loan. §1.7.3 · p. 50 The book does not show them, so here is the basic one.

Filling the gap: updating R with Givens rotations

We have \([\mathbf{R} \mid \mathbf{d}]\), so the current cost is \(\norm{\mathbf{R}\mathbf{x} - \mathbf{d}}^2\) plus a constant. One new scalar measurement, already whitened, adds a term \((\mathbf{a}\T\mathbf{x} - \beta)^2\). The new problem is the least-squares problem of the stacked matrix

\[ \left[\begin{array}{c|c} \mathbf{R} & \mathbf{d} \\ \mathbf{a}\T & \beta \end{array}\right] , \]

which is upper-triangular except for its last row. A Givens rotation is a rotation in the plane of two rows. To zero entry \(a_c\) of the new row against row \(c\) of \(\mathbf{R}\), set \(r = \sqrt{R_{cc}^2 + a_c^2}\), \(\cos = R_{cc}/r\), \(\sin = a_c/r\), and replace the two rows by

\[ \begin{aligned} \text{row } c &\leftarrow \cos \cdot (\text{row } c) + \sin \cdot (\text{new row}) , \\ \text{new row} &\leftarrow -\sin \cdot (\text{row } c) + \cos \cdot (\text{new row}) . \end{aligned} \]

The new diagonal entry is \(r\) and the new row's entry in column \(c\) is \((-a_c R_{cc} + R_{cc} a_c)/r = 0\). A rotation is orthogonal, so by the argument of Day 2 the cost function is unchanged. Repeat for each column from the first nonzero of \(\mathbf{a}\) to the last. What remains of the new row is a single number in the right-hand-side column, which only adds to the residual.

Two things to notice. Rows of \(\mathbf{R}\) above the first nonzero of \(\mathbf{a}\) are never touched. And mixing in row \(c\) can put nonzeros into later entries of the new row that started as zeros, so one rotation is usually not enough.

Try it: \(\mathbf{R}\) belongs to five poses in a chain. Rotate in a loop closure to the first pose, then switch to the measurement that touches only the newest pose.

Notice that the loop closure x₅ − x₁ = 4.6 needs 5 rotations and changes every row of R, and the estimate moves from (0, 1, 2.1, 3, 4) to (0, 1.12, 2.34, 3.36, 4.48). The measurement x₅ = 4.4 needs one rotation and changes one row. Yet it also moves every estimate, because back-substitution passes the change in x₅ on to all the others.

This is yesterday's tree rule in matrix clothing. For a chain, the rows from the first nonzero down to the last are the path to the root. The tree is more precise for general graphs, because it also skips branches that lie between the two in the ordering but are unrelated.

iSAM1 had two weak spots. The column order was the order in which variables arrived, so loop closures produced growing fill-in. And all of \(\mathbf{R}\) was built on one linearization point. Its remedy was a periodic batch step: linearize the full factor graph again, at fixed intervals or when fill-in became unwieldy. §1.7.3 · p. 50 The work between two batch steps was small, but the batch steps themselves grew with the map.

2. iSAM2: edit the tree, and be lazy three times

iSAM2 stores the posterior as a Bayes tree and applies the update of Day 4 for every new measurement. §1.7.3 · p. 50 Three practical questions remain, and the book answers each on p. 51.

Which ordering for the part that is re-eliminated? Only the variables of the affected cliques are eliminated again, so only they can be reordered. Running COLAMD on them alone is one option. iSAM2 does better with constrained COLAMD: it forces the most recently accessed variables to the end of the ordering, which puts them in the root clique, and orders the rest well. The reason is a bet about the future. The next factors will almost surely involve the newest pose, and if that pose is already in the root, the path to the root is as short as it can be. The book expects later updates to be efficient "in most cases, except for large loop closures". §1.7.3 · p. 51

Which variables need a new value? Back-substitution in the tree starts at the root and moves towards the leaves, each clique using the values of its separator. A clique's solution changes only through its separator, so if the values handed down have changed by less than a small threshold, there is no need to descend further. §1.7.3 · p. 51 The widget above shows why this matters: an update that changes one row of \(\mathbf{R}\) can still shift every estimate a little, and the threshold decides how far down the tree those shifts are followed.

Which factors are linearized again? Only those containing a variable whose estimate has moved away from its linearization point by more than a threshold. §1.7.3 · p. 51 The iSAM2 paper calls this fluid relinearization: there are no batch steps any more.

Filling the gap: why relinearization reaches further than a new factor

Adding a factor leaves all old factors as they were. The affected cliques can be turned back into factors as they are, and only cliques where the new factor's variables are frontal, plus their ancestors, are redone.

Relinearizing variable \(v\) is different: every factor that touches \(v\) gets a new \(\mathbf{A}_i\) and \(\mathbf{b}_i\). Such a factor entered the tree at the clique where the first of its variables was eliminated, and \(v\) may be only a separator variable there. So every clique that contains \(v\) at all, as frontal or as separator, holds outdated numbers and must be redone, together with all ancestors. The cliques cannot simply be recycled either. The method has to go back to the original nonlinear factors, and the contributions of the untouched sub-trees must have been cached during elimination. The book's verdict: this affects larger parts of the tree, but is in most cases still much cheaper than recomputing all of it. §1.7.3 · p. 51

Put together, one iSAM2 step looks like this (a summary of pp. 50–51, not the paper's exact listing):

when new factors (and new variables) arrive:
  1. mark the cliques on the paths from the new factors' variables to the root
  2. mark every clique containing a variable that has moved past the
     relinearization threshold, and the paths from those to the root
  3. turn the marked part back into a factor graph: relinearized original
     factors where needed, cached summaries of the sub-trees below, the new factors
  4. order its variables with constrained COLAMD (recent variables last)
     and eliminate: this is the new top of the Bayes tree
  5. re-attach the untouched sub-trees
  6. back-substitute from the root; stop going down a branch where the
     change is below the threshold

3. When is an update cheap?

Go back to the Day 4 widget with today's vocabulary. While the robot explores, each new factor involves the newest pose and something recent. Those variables are in or next to the root, so 3 or 4 variables are re-eliminated, independent of how long the trajectory is. That is the regime in which incremental smoothing gives a full-trajectory estimate at a nearly constant cost per step.

A loop closure ties the newest pose to an old one that sits deep in the tree. The whole path between them is redone, and for a large loop this can be most of the tree. No ordering trick removes that cost, since the new measurement really does change what is known about everything on the loop. Afterwards the old variable is near the root and the following steps are cheap again.

In plain words

Keep your notes in a binder with the newest pages on top. A new observation about today only needs the top pages rewritten. Discovering that today's place is the same as a place from chapter one means rewriting everything in between. Once that is done, you are back to rewriting only the top pages.

Both algorithms are implemented in the GTSAM library, and the book reports that they have been applied to many robotics estimation problems, at sizes that reach into the millions. §1.7.3 · p. 51

Common mistakes

  • "Incremental means approximate." For the linear problem the updated tree is exactly what a batch factorization would give. The approximations are the two thresholds, which trade a little accuracy for speed.
  • "iSAM is a filter." It is a smoother: every past pose stays in the estimate and can still be corrected, as a loop closure shows.
  • "A loop closure is cheap because it is one factor." The cost depends on where its variables sit in the tree, not on the number of factors.

Check yourself

Q1. A row of R reads (3, …) in column c and the new row has 4 in column c. After the Givens rotation, what is the diagonal entry R_cc?

r = √(3² + 4²) = 5. The rotation moves all the weight of the two entries into the row of R and leaves zero in the new row.

Q2. R has 100 columns in arrival order. A new measurement row has its first nonzero in column 97. How many rows of R can change?

Rotations start at the first nonzero and move right. Rows above it are never mixed with the new row.

Q3. Why does iSAM2 force the most recently used variables to the end of the elimination ordering?

Variables eliminated last form the root clique. New factors usually involve recent variables, so the affected path to the root stays short.

Q4. Variable v is frontal in clique C₁ and a separator variable in its child C₂. Its estimate has moved past the relinearization threshold. Which cliques are redone?

Relinearization changes the factors on v, and some of them were absorbed in C₂, where v is a separator. All cliques containing v are redone, plus everything above them.

Q5. During back-substitution a clique receives separator values that changed by far less than the threshold. What does iSAM2 do?

A clique's solution depends on the rest of the tree only through its separator. If that input has barely changed, neither will the outputs further down.

Recap

  1. A new measurement row can be rotated into \(\mathbf{R}\) with Givens rotations. Rows above its first nonzero are untouched. This is the matrix view of "only the path to the root".
  2. iSAM1 updates \(\mathbf{R}\) this way and relinearizes the full graph in periodic batch steps.
  3. iSAM2 edits the Bayes tree: re-eliminate the affected cliques, with recently used variables ordered last so they sit in the root.
  4. It back-substitutes only as far as the solution changes, and relinearizes only variables that moved past a threshold. Relinearization redoes every clique containing such a variable.
  5. Exploration costs a few variables per step. A large loop closure can cost most of the tree.
