Range sensors, point clouds, and occupancy grids

Today's big idea

A range sensor reports distances along known directions. Each beam says two things: the space it crossed is empty, and something solid sits where it ended. An occupancy grid keeps, for every cell, the probability that the cell is occupied, and the log-odds form reduces each new beam to one addition per cell.

Weeks 2 to 7 were about the back-end: estimating the trajectory. This chapter assumes that job is done. The poses are known, and the question is how to build a dense map from them, one that describes all the geometry the sensor saw and not only a few landmarks. Planning, obstacle avoidance, and manipulation need that detail. Ch. 5 intro · p. 119

1. Range from time of flight

A LiDAR emits a laser pulse, waits for the reflection, and measures the delay. Light travels to the surface and back, so the range is half the round trip: §5.1.1 · p. 120

\[ r = \frac{c\,(t_{\text{detect}} - t_{\text{emit}})}{2}. \tag{5.1} \]

With \(c \approx 3\times10^{8}\) m/s, a delay of 200 ns gives \(r = 3\times10^{8} \times 200\times10^{-9} / 2 = 30\) m. Turn it around: to resolve 1 cm in range the electronics must resolve \(2 \times 0.01 / (3\times10^{8}) \approx 67\) picoseconds.

One beam gives one distance. Sweep an array of \(B\) beams through a full turn with \(M\) steps and you get a range image \(\mathbf{R} \in \R^{B\times M}\): one range per beam and per step. An RGB-D camera returns the same kind of data on a pixel grid, a depth map \(\mathbf{I}_D \in \R^{H\times W}\) next to the colour image. Early RGB-D cameras project an infrared pattern and read depth from its distortion, which sunlight washes out, so they are indoor sensors. §5.1.1 · pp. 120–121

2. From ranges to points

A range is only useful with its direction. The sensor's calibration gives each beam two angles: the azimuth \(\phi\), measured around the vertical axis, and the inclination \(\theta\), measured up from the horizontal plane. The point hit by the beam, in the sensor's own frame, is §5.1.2 · p. 121

\[ x = r\cos\theta\cos\phi, \qquad y = r\cos\theta\sin\phi, \qquad z = r\sin\theta. \tag{5.2–5.4} \]

Example: \(r = 10\) m, \(\theta = 30^\circ\), \(\phi = 60^\circ\). The ground distance is \(10\cos 30^\circ = 8.66\) m, so \(x = 8.66 \times 0.5 = 4.33\), \(y = 8.66 \times 0.866 = 7.50\), \(z = 10 \times 0.5 = 5.00\) m. Check: \(4.33^2 + 7.50^2 + 5.00^2 = 100\). A planar 2D LiDAR is the case \(\theta = 0\): \((x, y) = (r\cos\phi,\; r\sin\phi)\).

Filling the gap: back-projecting a depth pixel

For an RGB-D camera the book writes the conversion in one line, \(\mathbf{p} = \mathbf{K}^{\dagger}\mathbf{x}\), equation (5.5). Unpacked for the usual pinhole camera, it reads as follows. A camera with focal lengths \(f_x, f_y\) (in pixels) and principal point \((c_x, c_y)\) projects a point \((X, Y, Z)\) in its own frame to the pixel

\[ u = f_x \frac{X}{Z} + c_x, \qquad v = f_y \frac{Y}{Z} + c_y . \]

A colour image loses \(Z\), so one pixel corresponds to a whole ray. A depth map stores \(Z\) at each pixel, and then the two equations can be solved for the other two coordinates:

\[ X = \frac{(u - c_x)\,Z}{f_x}, \qquad Y = \frac{(v - c_y)\,Z}{f_y}, \qquad Z = \mathbf{I}_D(u, v). \]

Example: \(f_x = f_y = 500\), \((c_x, c_y) = (320, 240)\), pixel \((420, 240)\), depth 2 m. Then \(X = 100 \times 2 / 500 = 0.4\) m, \(Y = 0\), \(Z = 2\) m.

The result is a point cloud \(\mathsf{P} = \{\mathbf{p}_1, \dots, \mathbf{p}_N\}\) in the sensor frame. A cloud from a depth map is organized: neighbours in the image are neighbours in the list, so finding the points next to a given one is an index lookup. A cloud from a moving LiDAR is not that simple. The sensor travels during the sweep, so each beam is fired from a slightly different pose. To undistort the cloud you need the motion during the sweep (from an IMU or odometry) and the firing time of each beam. §5.1.2 · pp. 121–122

3. What should a dense map store?

The chapter is built on three questions: which quantity to estimate, which geometric abstraction to use, and which data structure to store it in. §5.2 · pp. 122–123 For the first question there are two common answers, occupancy (today) and distance to the nearest surface (tomorrow).

An occupancy grid cuts space into cells \(m_k\). Each cell is either occupied or empty, we do not know which, and the map stores the probability \(p(m_k \mid \mathbf{z}_{1:t}, \mathbf{x}_{1:t})\) that it is occupied given all measurements \(\mathbf{z}_{1:t}\) and all sensor poses \(\mathbf{x}_{1:t}\). A value near 1 means occupied, near 0 means free, and 0.5 means the data say nothing. Mapping is then a binary classification problem, solved once per cell. §5.2.1 · pp. 123–124

4. The log-odds update

The book states the update rule directly, in terms of the odds \(o = p / (1 - p)\) and the log-odds \(l = \log o\): §5.2.1 · p. 124

\[ l(m_k \mid \mathbf{z}_{1:t}) = l(m_k \mid \mathbf{z}_{1:t-1}) + l(m_k \mid \mathbf{z}_t). \tag{5.6} \]

Filling the gap: where equation (5.6) comes from

Fix one cell \(m_k\) and drop the poses from the notation, as the book does. Bayes' rule (Week 1 · Day 2), applied to the newest measurement \(\mathbf{z}_t\), gives

\[ p(m_k \mid \mathbf{z}_{1:t}) = \frac{p(\mathbf{z}_t \mid m_k, \mathbf{z}_{1:t-1})\; p(m_k \mid \mathbf{z}_{1:t-1})}{p(\mathbf{z}_t \mid \mathbf{z}_{1:t-1})}. \]

Assumption 1, conditional independence: once you know whether the cell is occupied, older measurements tell you nothing more about the new one, so \(p(\mathbf{z}_t \mid m_k, \mathbf{z}_{1:t-1}) = p(\mathbf{z}_t \mid m_k)\). Apply Bayes' rule a second time to that factor, \(p(\mathbf{z}_t \mid m_k) = p(m_k \mid \mathbf{z}_t)\,p(\mathbf{z}_t) / p(m_k)\), and substitute:

\[ p(m_k \mid \mathbf{z}_{1:t}) = \frac{p(m_k \mid \mathbf{z}_t)\; p(\mathbf{z}_t)\; p(m_k \mid \mathbf{z}_{1:t-1})}{p(m_k)\; p(\mathbf{z}_t \mid \mathbf{z}_{1:t-1})}. \]

The same steps for the opposite event "cell is free", written \(\neg m_k\), give the same formula with \(\neg m_k\) in place of \(m_k\). Divide the first by the second. The two awkward terms \(p(\mathbf{z}_t)\) and \(p(\mathbf{z}_t \mid \mathbf{z}_{1:t-1})\) appear in both and cancel:

\[ \underbrace{\frac{p(m_k \mid \mathbf{z}_{1:t})}{p(\neg m_k \mid \mathbf{z}_{1:t})}}_{o(m_k \mid \mathbf{z}_{1:t})} = \underbrace{\frac{p(m_k \mid \mathbf{z}_t)}{p(\neg m_k \mid \mathbf{z}_t)}}_{o(m_k \mid \mathbf{z}_t)} \cdot \underbrace{\frac{p(m_k \mid \mathbf{z}_{1:t-1})}{p(\neg m_k \mid \mathbf{z}_{1:t-1})}}_{o(m_k \mid \mathbf{z}_{1:t-1})} \cdot \underbrace{\frac{p(\neg m_k)}{p(m_k)}}_{1 / o(m_k)} . \]

Because \(p(\neg m_k \mid \cdot) = 1 - p(m_k \mid \cdot)\), each ratio is an odds as in equation (5.7). Take the logarithm and the product becomes a sum:

\[ l(m_k \mid \mathbf{z}_{1:t}) = l(m_k \mid \mathbf{z}_{1:t-1}) + l(m_k \mid \mathbf{z}_t) - l(m_k). \]

The last term is the log-odds of the prior. With the usual prior \(p(m_k) = 0.5\) it is \(\log 1 = 0\), and what remains is equation (5.6). Assumption 2, independent cells, is what allowed us to do all of this for one cell at a time. To read a probability back out, invert the definition: \(p = 1 / (1 + e^{-l})\).

5. The inverse sensor model, and a grid you can fill

The term \(l(m_k \mid \mathbf{z}_t)\) is the inverse sensor model: it goes from a measurement to a belief about a cell, the reverse of a model that predicts measurements. For a narrow laser beam a simple piecewise-constant model is enough. §5.4.4.1 · p. 138

Where the cell isWhat the beam saysUpdate to l
Between the sensor and the beam's end pointThe beam passed, so the cell is probably freeAdd a negative constant
Contains the end pointSomething reflected the beam hereAdd a positive constant
Beyond the end point, or off the beamNothingLeave unchanged

Worked example. Say a hit means \(p = 0.7\), so \(l = \log(0.7/0.3) = +0.847\), and a pass means \(p = 0.4\), so \(l = \log(0.4/0.6) = -0.405\). A cell that starts at \(l = 0\) and is hit three times reaches \(l = 2.542\), which is \(p = 1/(1 + e^{-2.542}) = 0.93\). Two later beams that pass through it bring it to \(l = 1.731\), \(p = 0.85\). No measurement is ever stored: the single number \(l\) summarizes all of them.

Try it: the map below already holds one scan. Press "Scan here" twice and watch the probe cell on the lower face of the box. Then press "Auto tour".

Notice the probe cell go 0.70, 0.84, 0.93 as in the worked example. Notice also what stays half-tone after the first scan: the regions hidden behind the box and behind the thin wall, the pillar included. Unknown is not the same as free, and only moving the robot resolves it.

Two limits of the grid follow from its assumptions. Treating cells as independent ignores that walls are continuous, so a grid cannot guess the occupancy of an unobserved cell from its neighbours. And the cell size is fixed before mapping starts, so the resolution is the same everywhere. §5.2.1 · p. 124 Days 4 and 5 return to both.

Common mistakes

  • "θ in (5.2)–(5.4) is measured from the z axis." Here it is measured from the horizontal plane, which is why \(z = r\sin\theta\). The physics convention (angle from the z axis) swaps the sine and cosine of \(\theta\).
  • "A cell at p = 0.5 is half full." It means no information. The cell is either occupied or free; the probability describes what we know.
  • "The inverse sensor model is the sensor's noise model." A noise model is \(p(\mathbf{z} \mid m)\), from world to measurement. The inverse model is \(p(m_k \mid \mathbf{z}_t)\), from measurement to world, and it is usually designed by hand.

Check yourself

Q1. A LiDAR must resolve 1.5 cm in range. What timing resolution does it need?

From (5.1), a range change of 0.015 m is a delay change of 2 × 0.015 / (3 × 10⁸) = 10⁻¹⁰ s = 100 ps. The factor 2 is the round trip.

Q2. A beam with azimuth 90° and inclination 30° returns r = 20 m. Where is the point in the sensor frame?

Ground distance 20 cos 30° = 17.3 m, all of it along y because the azimuth is 90°. Height z = 20 sin 30° = 10 m. The second option is what you get if you measure the inclination from the z axis.

Q3. A cell starts at p = 0.5. A hit means p = 0.7 and a pass means p = 0.4. After two hits and one pass, what is its occupancy probability?

Odds multiply: (7/3) × (7/3) × (2/3) = 3.63, so p = 3.63 / 4.63 = 0.78. In log-odds: 0.847 + 0.847 − 0.405 = 1.289. Averaging the three probabilities (0.60) is not Bayes' rule.

Q4. A beam returns r = 5 m. What does the piecewise-constant model do to a cell 7 m from the sensor in the same direction?

The beam stopped at 5 m, so it carries no information about what lies behind. The cell keeps whatever log-odds it had, which is 0 (unknown) if nothing else has observed it.

Recap

  1. Time of flight gives range, \(r = c\,\Delta t / 2\). A scan is a range image or depth map, and with the beam angles or camera intrinsics it becomes a point cloud in the sensor frame.
  2. \(x = r\cos\theta\cos\phi\), \(y = r\cos\theta\sin\phi\), \(z = r\sin\theta\), with \(\theta\) measured from the horizontal plane.
  3. An occupancy grid stores one probability per cell and treats cells as independent.
  4. Bayes' rule in log-odds form is an addition: \(l \leftarrow l + l(m_k \mid \mathbf{z}_t)\), with \(p = 1/(1 + e^{-l})\). The prior term vanishes for a prior of 0.5.
  5. A beam lowers \(l\) in the cells it crosses, raises it in the cell where it ends, and leaves the rest unknown.
