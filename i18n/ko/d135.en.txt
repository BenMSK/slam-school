Replace the class label stored in each map element by a feature vector from a foundation model. Building the map is then averaging: every view contributes a feature for each element it sees. Using the map is comparing: encode the question, take inner products with the stored features, and keep the elements that score high. 1. Swap the label for a feature
@@ 12
A class label is a coarse description. The book's toolbox example makes the point: "tool" is true but useless, "hammer" is better, and colour, material, use, or the sound an object makes do not fit in one label at all. Rare objects are missing from any list. <span class="src">§17.3 · pp. 499–500</span> So an open-vocabulary map keeps the geometry of <a href="#d45">Week 8</a> and changes what is attached to it. The map is a set \(\mathcal{M} \triangleq \{m_k\}\) of <strong>map elements</strong>
@@ 13
where \(\mathbf{p}_k\) is the geometric part (a 3D point, a voxel location, a mesh face) and \(\mathbf{f}_k\) is a feature vector. The geometry comes from an upstream SLAM system. <span class="src">§17.3.1 · p. 501</span> The book assumes posed RGB-D frames of a static scene, processed one after another. <span class="src">§17.3 · p. 500</span> The features can sit on the cells of a 2D grid (VLMaps, which suits navigation), on an unordered set of 3D points (ConceptFusion, OpenScene), or in a TSDF volume (Open-Fusion; see <a href="#d44">Week 8 · Day 2</a>). <span class="src">§17.3.1 · p. 501</span>
@@ 14
2. A feature for every pixel
@@ 15
CLIP describes a whole image with one vector, but a map needs a vector per pixel. There are two routes. <span class="src">§17.3.1 · p. 501</span>
@@ 16
<strong>Route A: a model that outputs dense features.</strong> Fine-tune a model like CLIP on a segmentation dataset so that it emits pixel-level features (LSeg, used by OpenScene and VLMaps) or region-level ones (SEEM, used by Open-Fusion for speed). The cost: evidence suggests these fine-tuned features lose some of the rare, long-tail concepts the original CLIP features hold.
@@ 17
<strong>Route B: keep CLIP untouched and do arithmetic.</strong> ConceptFusion combines whole-image context with object crops: <span class="src">§17.3.1 · pp. 501–502</span>
@@ 18
<strong>Global feature</strong> \(\mathbf{f}^G = f(\mathbf{I})\): encode the entire image.
@@ 19
<strong>Local features</strong>: run \(\texttt{Seg}(\mathbf{I})\), turn each mask into a bounding box, crop the image to it, and encode the crop: \(\mathbf{f}^L_i = f(\mathbf{I}_i)\).
@@ 20
<strong>Merge per mask</strong>: \(\mathbf{f}^P_i = w_i \mathbf{f}^G + (1 - w_i)\,\mathbf{f}^L_i\) with \(w_i \in [0,1]\). The weights are set to emphasize local features that differ from the global one and from the other local ones.
@@ 21
<strong>Per pixel</strong>: \(\mathbf{f}^P_{u,v}\) is the sum of the mask features over all masks with \(\mathbf{Z}_i[u,v] = 1\), scaled to unit length.
@@ 22
(On p. 502 this last bullet prints \(\mathbf{f}^L_i\) in the sum; its own description means \(\mathbf{f}^P_i\).) Back-project each pixel with its depth, as in <a href="#d43">Week 8 · Day 1</a>, and you have a point cloud in which every point carries a feature. The book calls this a <strong>range-feature observation</strong>. <span class="src">§17.3.1 · p. 502</span>

3. Fusing many views into one feature
@@ 24
The same 3D point is seen in many frames, so its features must be combined. VLMaps simply averages all features that fall in the same grid cell. ConceptFusion keeps a feature \(\mathbf{f}_k\) and a <strong>confidence</strong> \(c_k\) per point and updates both with each new pixel feature: <span class="src">§17.3.1 · p. 502</span>
@@ 25
with \(\alpha = e^{-\gamma^2/2\sigma^2}\), where \(\gamma\) is the radial distance to the camera center and \(\sigma\) a scale. Small \(\gamma\) gives \(\alpha\) near 1; large \(\gamma\) gives a small \(\alpha\).
@@ 26
<strong>Numbers</strong> (two dimensions, to keep it readable). A point has \(c_k = 2\), \(\mathbf{f}_k = (1, 0)\). A new view gives \(\mathbf{f}^P = (0, 1)\) at \(\gamma = \sigma\), so \(\alpha = e^{-1/2} = 0.607\). Then \(\mathbf{f}_k \leftarrow (2 \cdot (1,0) + 0.607 \cdot (0,1))/2.607 = (0.767, 0.233)\) and \(c_k \leftarrow 2.607\).
@@ 27
Filling the gap: the update is a weighted mean, and averaging removes noise
@@ 28
<strong>Unrolling.</strong> Start a point at \(c_k = 0\) and feed it features \(\mathbf{f}_1, \dots, \mathbf{f}_n\) with weights \(\alpha_1, \dots, \alpha_n\). Claim: after \(n\) updates \(c_k = \sum_t \alpha_t\) and \(c_k \mathbf{f}_k = \sum_t \alpha_t \mathbf{f}_t\). It holds after one update. If it holds after \(n-1\), then (17.2) times its denominator reads \(c_k^{\text{new}} \mathbf{f}_k^{\text{new}} = c_k \mathbf{f}_k + \alpha_n \mathbf{f}_n = \sum_{t \le n} \alpha_t \mathbf{f}_t\). So
@@ 29
The map never stores the individual views, only this running weighted mean and the sum of weights. It is the same trick as the TSDF weight in <a href="#d44">Week 8 · Day 2</a>.
@@ 30
<strong>Why average.</strong> Model each view's feature as the true one plus an independent error, \(\mathbf{f}_t = \mathbf{f} + \mathbf{e}_t\), each of the \(d\) components of \(\mathbf{e}_t\) having variance \(s^2\). With equal weights the mean's error has variance \(s^2/n\) per component, so its squared length is about \(d s^2 / n\). That error is mostly perpendicular to \(\mathbf{f}\) (length 1), so
@@ 31
For \(d = 8\), \(s = 0.6\): one view gives \(1/\sqrt{3.88} = 0.51\), twenty views give \(1/\sqrt{1.144} = 0.93\).
@@ 32
<strong>One caution.</strong> A mean of unit vectors is shorter than 1 (the example above has length 0.80). The arg max in (17.4) below does not care, but a threshold on \(\langle \mathbf{f}_k, \mathbf{f}_T \rangle\) does: normalize \(\mathbf{f}_k\) first.
@@ 33
Averaging is not the only choice. To avoid averaging high-dimensional vectors and to resist outliers, the book lists alternatives: keep a buffer of features per element and store its <strong>medoid</strong> (the member closest to all the others); cluster the buffer and keep a few centroids, or the member nearest the centroid of the majority cluster; or, in Open-Fusion, store in each voxel only a key into a dictionary of features. <span class="src">§17.3.1 · pp. 502–503</span>

4. Asking the map a question
@@ 35
To label the map with classes chosen today, encode a prompt list \(\mathsf{C}\) with the text encoder and give each element its best-matching prompt: <span class="src">§17.3.1 · p. 503</span>
@@ 36
This is yesterday's classifier (17.1) with a map feature in place of an image feature. \(\mathsf{C}\) plays no part in building the map and can be changed at will. The main use, though, is the open-ended <strong>query</strong>: encode any text \(T\), score every element by \(\langle \mathbf{f}_k, \mathbf{f}_T \rangle\), keep those above a threshold, and cluster the kept points in space to separate instances.
@@ 37
Try it: the query is "a comfy place to sit" with one noisy view. Slide "Views fused" up to 20. Then try the other queries and move the threshold.
@@ 38
Notice that with one view only 4 cells pass the threshold, one of them wrong, and 11 are missed. With 20 views all 14 sofa and armchair cells are retrieved and nothing else, and the mean cosine to the clean features rises from 0.49 to 0.93, as the formula above predicts.
@@ 39
The query need not be text. Any modality with an aligned encoder works; ConceptFusion shows a click on a map point (use that point's own \(\mathbf{f}_k\)), an image, and an audio clip. A map built from vision-only features such as DINO loses text queries but still supports image and click queries. <span class="src">§17.3.1 · pp. 503–504</span>

5. One feature per object
@@ 41
Dense feature maps scale poorly because the vectors are large. Count it: a million points, each with a 768-number feature (the size the book quotes for one CLIP model on p. 510) at 4 bytes per number, is about 3 GB. Nearby points usually belong to the same object and share semantics, so store the feature once per object. <span class="src">§17.3.2 · p. 504</span> Two hundred objects need 200 × 768 × 4 bytes, about 0.6 MB.
@@ 42
The <strong>object map</strong> is a set \(\mathsf{V}_O = \{o_j\}_{j=1}^{J}\). Each object has a point cloud \(\mathsf{P}_{o_j}\), a feature \(\mathbf{f}_{o_j}\), and a detection count \(n_{o_j}\). For each new frame: <span class="src">§17.3.2 · pp. 504–505</span>
@@ 43
<strong>Extract.</strong> For each mask from \(\texttt{Seg}(\mathbf{I})\), encode its crop to get \(\mathbf{f}^M_i\) and back-project its pixels to a point cloud \(\mathsf{P}^M_i\) in the map frame.
@@ 44
<strong>Associate.</strong> Compare each mask with existing objects. Geometric similarity \(\phi_{geo} \in [0,1]\) is the fraction of mask points that have a neighbour in the object's cloud within a distance \(\delta_{nn}\). Semantic similarity is \(\phi_{sim} = \tfrac{1}{2}(\langle \mathbf{f}_i, \mathbf{f}_{o_j} \rangle + 1) \in [0,1]\). Combine or threshold them. An unmatched mask starts a new object.
@@ 45
<strong>Fuse.</strong> On a match, \(\mathbf{f}_{o_j} \leftarrow (n_{o_j}\mathbf{f}_{o_j} + \mathbf{f}_i)/(n_{o_j}+1)\), \(\mathsf{P}_{o_j} \leftarrow \mathsf{P}_{o_j} \cup \mathsf{P}^M_i\), \(n_{o_j} \leftarrow n_{o_j}+1\). This is (17.2) with \(\alpha = 1\) and the count as confidence.
@@ 46
<strong>Clean up.</strong> Now and then merge duplicate objects, and drop those with a low count.
@@ 47
<strong>Numbers.</strong> A mask cloud has 200 points; 150 have an object point within \(\delta_{nn}\), so \(\phi_{geo} = 0.75\). The features have inner product 0.6, so \(\phi_{sim} = 0.8\). If both pass your thresholds and the object had \(n = 4\), its feature becomes \((4\mathbf{f}_o + \mathbf{f}_i)/5\) and \(n = 5\).
@@ 48
Queries now return whole objects: \(o^* = \argmax_{o \in \mathsf{V}_O} \langle \mathbf{f}_o, \mathbf{f}_T \rangle\). In the book's example, "something to drink" scores high on a soda can, whose point cloud can go straight to a motion planner. <span class="src">§17.3.2 · p. 506</span>
@@ 49
<strong>"The prompt list must be chosen before mapping."</strong> Neither \(\mathsf{C}\) nor the query enters the map. Only features do.
@@ 50
<strong>"A retrieved element is a detection."</strong> Arg max always returns something, and a threshold is a setting you chose. Neither says the object exists.

Q2. With equal weights, how many views must you average to halve the per-component noise of a fused feature?
@@ 54
It cannot be halved by averaging
@@ 55
The variance of a mean of n independent errors is s²/n, so the standard deviation is s/√n. Halving it needs n = 4.
