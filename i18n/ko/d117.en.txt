The rendering equation of Day 2 does not care how density and colour are stored. Put them in one network and the map is compact and fills holes, but it is slow, cannot grow, and forgets. 1. Why one MLP is slow, and what replaced it
@@ 12
The original NeRF asks one MLP for the colour and density of every sample on every ray. Each answer runs the whole network, so every weight takes part in every query, forward and backward. Training is slow as a result. Later methods moved some or all of the scene into explicit data structures with fast access. <span class="src">§14.2.2 · p. 403</span>

Filling the gap: trilinear interpolation, and why it makes updates local
@@ 38
A grid stores values only at its nodes. <strong>Linear interpolation</strong> fills in between. In 1D, at a fraction \(s \in [0, 1]\) of the way from node \(i\) to node \(i+1\),
@@ 39
In 2D (bilinear) do this along \(x\), then along \(y\). The four corner values get weights that are products of 1D weights. With \(f_{00} = 1\), \(f_{10} = 3\), \(f_{01} = 2\), \(f_{11} = 6\) and \((s_x, s_y) = (0.25, 0.5)\):
@@ 40
<strong>Trilinear</strong> interpolation is the 3D version: eight corners, each weighted by a product of three such factors. Two things follow. The weights are non-negative and sum to 1, so the result is a smooth average of the corner values. And the derivative of \(f\) with respect to a node value is that node's weight, which is zero for every node outside the cell. A loss on one sample therefore changes eight numbers, not the whole map.

2. Neural fields: outputs other than radiance
@@ 42
A field that maps position to colour and density is one choice of output. Fields that output something else are called <strong>neural fields</strong>. <span class="src">§14.2.3 · p. 404</span>
@@ 43
<strong>Surfaces.</strong> For accurate geometry from RGB images, the field can be a signed distance function (NeuS, VolSDF) or an occupancy field (UNISURF), still trained through volume rendering. A mesh is then extracted with marching cubes (<a href="#d46">Week 8 · Day 4</a>). <span class="src">§14.2.3 · pp. 404–405</span> To use equation (14.2), such a method needs a rule that turns signed distance or occupancy into opacity. The book does not give those rules, so see the cited papers for them.
@@ 44
<strong>Semantics.</strong> Give the network an extra output for a semantic label, and train it against 2D label images from many views. The result is a labelling that is consistent in 3D. More generally a field can fuse 2D feature maps from pre-trained foundation networks, which enables scene decomposition and editing by language prompt or by clicking. <span class="src">§14.2.3 · pp. 405–406 · Fig. 14.9</span>

@@ 80
<strong>Compression against speed.</strong> An MLP packs the whole field into its weights, which is compact but hard to interpret. A grid is interpretable, fast to read, and can be updated locally, at the cost of memory. This is the usual trade of time against space, and because SLAM must run in real time, explicit structures usually win. <span class="src">pp. 406–407</span>
@@ 81
<strong>Scene completion.</strong> An MLP is a continuous function, so it gives plausible values in small regions it never observed. A multi-resolution grid does the same. The smoothing reaches as far as the positional encoding's frequency or the grid's cell size allows. Points are discrete and have no such global smoothing. <span class="src">p. 407 · Fig. 14.11</span>
@@ 82
<strong>Dynamic allocation.</strong> SLAM discovers the scene's extent as it goes and must move parts of the map when a loop closes (<a href="#d1">Week 1 · Day 1</a>). An MLP or a voxel grid has fixed bounds and a fixed encoding or resolution, so such systems resort to several local models. Points can be added and moved freely. <span class="src">pp. 407–408 · Fig. 14.12</span>
@@ 83
<strong>Forgetting.</strong> With a global function, a parameter update made for one place changes the output everywhere. The system must keep feeding past observations back in as a training signal, which requires an explicit keyframe database. Relying less on a global function, or removing it, reduces the problem. <span class="src">p. 408</span>

What the widget's two learned models are: the "global function" is a sum of sines and cosines that span the whole interval. It stands in for an MLP in the one respect that matters here, that every parameter influences the output everywhere. The grid is 1D linear interpolation between node values. Explore without replay applies the least-squares fit to the new samples that changes the parameters as little as possible, which is where gradient descent on the new samples alone heads when it starts from the old parameters.

Filling the gap: why a global function forgets and a grid does not
@@ 88
Write either model as \(f(x) = \sum_k \theta_k\,\phi_k(x)\): parameters \(\theta_k\) times fixed basis functions \(\phi_k\). One gradient-descent step of size \(\eta\) on the squared error at a new position \(x_n\), where the residual is \(r = f(x_n) - y_n\), changes each parameter by \(\Delta\theta_k = -2\eta\,r\,\phi_k(x_n)\). The prediction at an <em>old</em> position \(x_o\) therefore moves by
@@ 89
The sum measures how much the two positions share parameters.
@@ 90
<strong>Grid.</strong> \(\phi_k(x)\) is the interpolation weight of node \(k\), which is zero unless \(x\) is in a cell next to that node. With cells 0.1 wide, \(x_n = 0.83\) and \(x_o = 0.31\) have no node in common, so the sum is 0 and the old prediction does not move.
@@ 91
<strong>Global.</strong> Take just three basis functions, \(1\), \(\sin\pi x\), \(\cos\pi x\). The sum is \(1 + \sin(0.83\pi)\sin(0.31\pi) + \cos(0.83\pi)\cos(0.31\pi) = 1 + \cos(0.52\pi) = 0.937\). With \(r = 0.5\) and \(\eta = 0.1\) the old prediction shifts by \(-2 \times 0.1 \times 0.5 \times 0.937 = -0.094\), although nothing was observed there.
@@ 92
Replaying old keyframes adds gradient steps that pull the old region back. That is the keyframe database the book says such maps require.
@@ 93
<strong>"A finer grid is always better."</strong> A fine grid stores more and smooths less: holes smaller than a coarse cell get filled, holes larger than a fine cell do not. Multi-resolution grids keep both.
@@ 94
<strong>"Hybrid grids have no forgetting."</strong> Table 14.1 rates them "Moderate". A hybrid still decodes its features with a small shared MLP, and coarse cells are shared by neighbouring regions.
@@ 95
<strong>"Compact means fast."</strong> The MLP is the most compact and the slowest to query, because all of its weights take part in every query.
