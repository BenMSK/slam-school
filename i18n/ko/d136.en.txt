1. When a vector is not enough: describe the object in words
@@ 11
Object features work best against short descriptive queries. They miss negation and affordances: "something to drink other than a soda can" still lands on the soda can. A feature also cannot be read by a person or an LLM. The alternative is a <strong>caption</strong>: keep the best image crops of each object, ask a VLM to describe the central object, and let an LLM merge the per-view captions. To answer a query, give an LLM the caption list and ask for the most relevant object. This handles complex queries that defeat feature retrieval, but is much slower than inner products. Some methods keep both. <span class="src">§17.3.2 · pp. 506–507</span>

HOV-SG finds floors as peaks in a histogram of point heights. For each region it takes the CLIP embeddings of the camera views inside it and reduces them to \(K\) representatives \(\mathbf{f}_{r_k}\) by k-means. Each representative votes for a category from a candidate list \(\mathsf{C}_R\), and the majority names the region: <span class="src">§17.3.2 · pp. 508–509</span>
@@ 30
<strong>Numbers.</strong> \(K = 5\), votes kitchen, kitchen, living room, kitchen, corridor: a kitchen, 3 of 5. For a query, a generative model splits the sentence into one concept per layer, and each is scored from the top layer down. With 2 floors, 5 regions per floor, and 30 objects per region (our numbers), a flat search compares the query with 300 objects; the layered search compares 2 + 5 + 30 = 37 features.

3. Features inside a radiance field
@@ 32
The radiance fields of <a href="#d116">Week 20</a> can carry language too. <strong>LERF</strong> gives a NeRF a second output, a semantic embedding at point \(\mathbf{x}\) and scale \(s\), rendered along a ray the way colour is and trained on CLIP embeddings of image crops at many scales. To query, it converts similarities into a <strong>relevancy score</strong> for each rendered embedding: <span class="src">§17.3.3 · p. 510</span>
@@ 33
where the canonical embeddings come from generic phrases such as "object", "things", "stuff", "texture".
@@ 34
Filling the gap: what (17.7) computes
@@ 35
Write \(a\) for the similarity with the text and \(b_i\) for the similarity with canonical phrase \(i\). Dividing top and bottom by \(e^{a}\) gives \(1/(1 + e^{\,b_i - a})\), which grows with \(a - b_i\). So the minimum is set by the largest \(b_i\): the score is \(1/(1 + e^{\,b_{\max} - a})\), and it exceeds 0.5 exactly when the query beats every generic phrase. A raw cosine cannot say that, because "object" is somewhat similar to everything.
@@ 36
<strong>Numbers.</strong> \(a = 0.30\) and \(b = 0.20, 0.25, 0.10, 0.28\): the score is \(1/(1 + e^{-0.02}) = 0.505\). With \(a = 0.22\) it is \(1/(1 + e^{0.06}) = 0.485\): the point looks more like a generic phrase than like the query.
@@ 37
<strong>LangSplat</strong> attaches language features to the Gaussians of a splat map, using CLIP vectors of SAM segments at three levels of granularity. A 512-number vector per Gaussian is too much memory, so it trains a scene-specific network that compresses each vector to 3 numbers, and a decoder that restores it. One scene varies far less than CLIP's training corpus, so 3 numbers suffice. <span class="src">§17.3.3 · pp. 510–511</span>

4. The task decides what an object is
@@ 39
With no class list, what is one object? The book's piano is one object if the task is to move it, more than 90 if the task is to play it (keys and pedals), hundreds if the task is to tune it. <span class="src">§17.3.4 · pp. 511–512</span> <strong>Clio</strong> poses the problem: given tasks in natural language, such as "clean backpacks" and "get condiment packets", build a map whose objects have the granularity the tasks need. It uses the <strong>Information Bottleneck</strong>. Let \(X\) be fine-grained primitives (over-segmented 3D pieces), \(\tilde{X}\) the clusters, \(Y\) the tasks. Find the assignment \(p(\tilde{x} \mid x)\) that solves <span class="src">§17.3.4 · p. 512</span>

Filling the gap: mutual information, and the cost of one merge
@@ 41
The <strong>mutual information</strong> measures how much knowing one variable tells you about another:
@@ 42
It is zero when the two are independent. In (17.8), a small \(I(X;\tilde{X})\) means strong compression (a single cluster gives 0); a large \(I(\tilde{X};Y)\) means the clusters still tell you which task a piece matters for; \(\beta\) sets the exchange rate.
@@ 43
Clio solves it greedily (Agglomerative Information Bottleneck): every primitive starts as its own cluster, neighbours are connected, and the pair with the smallest weight is merged, again and again: <span class="src">§17.3.4 · p. 513</span>
@@ 44
\(D_{\mathrm{JS}}\) is the Jensen–Shannon divergence. With \(\pi_i = p(\tilde{x}_i)/(p(\tilde{x}_i) + p(\tilde{x}_j))\), \(\pi_j = 1 - \pi_i\), and the mixture \(\bar{p} = \pi_i\, p(y \mid \tilde{x}_i) + \pi_j\, p(y \mid \tilde{x}_j)\),
@@ 45
The merged cluster has probability \(p(\tilde{x}_i) + p(\tilde{x}_j)\) and task distribution \(\bar{p}\), and \(d_{ij}\) is exactly the drop in \(I(\tilde{X};Y)\).
@@ 46
<strong>Numbers.</strong> Two clusters, each with \(p = 1/12\). Same \(p(y \mid x)\): \(D_{\mathrm{JS}} = 0\), merging is free. Distributions \((1, 0)\) and \((0, 1)\): \(\bar{p} = (\tfrac12, \tfrac12)\), each KL term is \(\log 2\), so \(d = \tfrac{2}{12} \times 0.693 = 0.116\) nats.
@@ 47
For \(p(y \mid x)\) Clio uses the cosine score between a primitive's averaged CLIP embedding and the task text as a proxy. <span class="src">§17.3.4 · pp. 512–513</span> Try it: press "Merge 5 times", then merge twice more. Then switch the task list to "clean backpacks only".
@@ 48
Notice that seven merges turn 12 primitives into 5 clusters (wall; backpack; chair and table; the two packets; napkin, wall and poster) and keep 97.0% of the task information. The eighth merge would cost 0.097 nats, eight times the seventh. With only the backpack task the cheap merges continue down to 3 clusters (99.6% kept): the packets are no longer objects. The toy adds a "neither task" outcome so each row sums to 1.
@@ 49
Clio clusters regions of free space the same way. As of the book's April 2026 edition, the book flags two weak points (the cosine proxy, and aggregating semantics across views), cites Bayesian Fields as a more grounded treatment, and notes that tasks must still be phrased specifically, mostly because of CLIP's limits. <span class="src">§17.3.4 · pp. 513–514</span>
