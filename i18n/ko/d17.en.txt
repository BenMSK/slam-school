@@ 11
Incremental smoothing and mapping keeps the whole trajectory in the estimate but does only the work a new measurement calls for. iSAM1 updates the matrix \(\mathbf{R}\) directly and starts over from time to time. iSAM2 edits the Bayes tree and is lazy in three places: it reorders only the variables it re-eliminates, re-solves only where the answer moved, and relinearizes only the factors whose variables moved.

1. iSAM1: add a row to R without refactoring
@@ 13
The first version, iSAM1, used the incremental matrix factorization methods of Golub and Van Loan. <span class="src">§1.7.3 · p. 50</span> The book does not show them, so here is the basic one.

Filling the gap: updating R with Givens rotations
@@ 15
We have \([\mathbf{R} \mid \mathbf{d}]\), so the current cost is \(\norm{\mathbf{R}\mathbf{x} - \mathbf{d}}^2\) plus a constant. One new scalar measurement, already whitened, adds a term \((\mathbf{a}\T\mathbf{x} - \beta)^2\). The new problem is the least-squares problem of the stacked matrix
@@ 16
which is upper-triangular except for its last row. A <strong>Givens rotation</strong> is a rotation in the plane of two rows. To zero entry \(a_c\) of the new row against row \(c\) of \(\mathbf{R}\), set \(r = \sqrt{R_{cc}^2 + a_c^2}\), \(\cos = R_{cc}/r\), \(\sin = a_c/r\), and replace the two rows by
@@ 17
The new diagonal entry is \(r\) and the new row's entry in column \(c\) is \((-a_c R_{cc} + R_{cc} a_c)/r = 0\). A rotation is orthogonal, so by the argument of <a href="#d14">Day 2</a> the cost function is unchanged. Repeat for each column from the first nonzero of \(\mathbf{a}\) to the last. What remains of the new row is a single number in the right-hand-side column, which only adds to the residual.
@@ 18
Two things to notice. Rows of \(\mathbf{R}\) above the first nonzero of \(\mathbf{a}\) are never touched. And mixing in row \(c\) can put nonzeros into later entries of the new row that started as zeros, so one rotation is usually not enough.
@@ 19
Try it: \(\mathbf{R}\) belongs to five poses in a chain. Rotate in a loop closure to the first pose, then switch to the measurement that touches only the newest pose.
@@ 20
Notice that the loop closure x₅ − x₁ = 4.6 needs 5 rotations and changes every row of R, and the estimate moves from (0, 1, 2.1, 3, 4) to (0, 1.12, 2.34, 3.36, 4.48). The measurement x₅ = 4.4 needs one rotation and changes one row. Yet it also moves every estimate, because back-substitution passes the change in x₅ on to all the others.
@@ 21
This is yesterday's tree rule in matrix clothing. For a chain, the rows from the first nonzero down to the last are the path to the root. The tree is more precise for general graphs, because it also skips branches that lie between the two in the ordering but are unrelated.
@@ 22
iSAM1 had two weak spots. The column order was the order in which variables arrived, so loop closures produced growing fill-in. And all of \(\mathbf{R}\) was built on one linearization point. Its remedy was a periodic batch step: linearize the full factor graph again, at fixed intervals or when fill-in became unwieldy. <span class="src">§1.7.3 · p. 50</span> The work between two batch steps was small, but the batch steps themselves grew with the map.
@@ 23
2. iSAM2: edit the tree, and be lazy three times
@@ 24
iSAM2 stores the posterior as a Bayes tree and applies the update of <a href="#d16">Day 4</a> for every new measurement. <span class="src">§1.7.3 · p. 50</span> Three practical questions remain, and the book answers each on p. 51.
@@ 25
<strong>Which ordering for the part that is re-eliminated?</strong> Only the variables of the affected cliques are eliminated again, so only they can be reordered. Running COLAMD on them alone is one option. iSAM2 does better with <strong>constrained COLAMD</strong>: it forces the most recently accessed variables to the end of the ordering, which puts them in the root clique, and orders the rest well. The reason is a bet about the future. The next factors will almost surely involve the newest pose, and if that pose is already in the root, the path to the root is as short as it can be. The book expects later updates to be efficient "in most cases, except for large loop closures". <span class="src">§1.7.3 · p. 51</span>
@@ 26
<strong>Which variables need a new value?</strong> Back-substitution in the tree starts at the root and moves towards the leaves, each clique using the values of its separator. A clique's solution changes only through its separator, so if the values handed down have changed by less than a small threshold, there is no need to descend further. <span class="src">§1.7.3 · p. 51</span> The widget above shows why this matters: an update that changes one row of \(\mathbf{R}\) can still shift every estimate a little, and the threshold decides how far down the tree those shifts are followed.
@@ 27
<strong>Which factors are linearized again?</strong> Only those containing a variable whose estimate has moved away from its linearization point by more than a threshold. <span class="src">§1.7.3 · p. 51</span> The iSAM2 paper calls this fluid relinearization: there are no batch steps any more.
@@ 28
Filling the gap: why relinearization reaches further than a new factor
@@ 29
Adding a factor leaves all old factors as they were. The affected cliques can be turned back into factors as they are, and only cliques where the new factor's variables are <em>frontal</em>, plus their ancestors, are redone.
@@ 30
Relinearizing variable \(v\) is different: every factor that touches \(v\) gets a new \(\mathbf{A}_i\) and \(\mathbf{b}_i\). Such a factor entered the tree at the clique where the first of its variables was eliminated, and \(v\) may be only a <em>separator</em> variable there. So every clique that contains \(v\) at all, as frontal or as separator, holds outdated numbers and must be redone, together with all ancestors. The cliques cannot simply be recycled either. The method has to go back to the original nonlinear factors, and the contributions of the untouched sub-trees must have been cached during elimination. The book's verdict: this affects larger parts of the tree, but is in most cases still much cheaper than recomputing all of it. <span class="src">§1.7.3 · p. 51</span>

3. When is an update cheap?
@@ 50
Go back to the <a href="#d16">Day 4</a> widget with today's vocabulary. While the robot explores, each new factor involves the newest pose and something recent. Those variables are in or next to the root, so 3 or 4 variables are re-eliminated, independent of how long the trajectory is. That is the regime in which incremental smoothing gives a full-trajectory estimate at a nearly constant cost per step.
@@ 51
A loop closure ties the newest pose to an old one that sits deep in the tree. The whole path between them is redone, and for a large loop this can be most of the tree. No ordering trick removes that cost, since the new measurement really does change what is known about everything on the loop. Afterwards the old variable is near the root and the following steps are cheap again.

<strong>"Incremental means approximate."</strong> For the linear problem the updated tree is exactly what a batch factorization would give. The approximations are the two thresholds, which trade a little accuracy for speed.
@@ 77
<strong>"iSAM is a filter."</strong> It is a smoother: every past pose stays in the estimate and can still be corrected, as a loop closure shows.
@@ 78
<strong>"A loop closure is cheap because it is one factor."</strong> The cost depends on where its variables sit in the tree, not on the number of factors.

@@ 105
A new measurement row can be rotated into \(\mathbf{R}\) with Givens rotations. Rows above its first nonzero are untouched. This is the matrix view of "only the path to the root".
@@ 106
iSAM1 updates \(\mathbf{R}\) this way and relinearizes the full graph in periodic batch steps.
@@ 107
iSAM2 edits the Bayes tree: re-eliminate the affected cliques, with recently used variables ordered last so they sit in the root.
@@ 108
It back-substitutes only as far as the solution changes, and relinearizes only variables that moved past a threshold. Relinearization redoes every clique containing such a variable.
