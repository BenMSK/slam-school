The object is the natural unit of long-term change. Finding a moved object again is a small place-recognition problem with few features and many look-alikes. Online, a mismatch between map and view can mean change, noise, or a wrong pose. Change-aware systems trust only short stretches of data that cannot have changed, reason per object, and keep for each object a probability that it is still there.

1. Objects from change, and finding them again
@@ 12
Change and objects explain each other. <strong>Object detection from changes</strong> clusters the surfaces that changed in a dense reconstruction into likely objects. It needs no semantic detector, but partial views mislead it: two touching objects removed together come out as one, and one object seen through occlusions comes out as several. <span class="src">§15.3.2.3 · p. 439</span>
@@ 13
<strong>Object instance re-localization</strong> tracks an object through long-term changes: given an earlier and a later scan, decide which instances correspond and estimate each one's 6-DoF motion. It resembles place recognition, with four added difficulties. <span class="src">§15.3.2.3 · pp. 439–440</span>
@@ 14
Detail
@@ 15
Arbitrary motion
@@ 16
An object can move any distance between observations
@@ 17
Few features
@@ 18
An object is far smaller than a scene, and small objects seen from afar give few measurements
@@ 19
Perceptual aliasing
@@ 20
A seminar room holds a hundred identical chairs. Which is which may not matter; one shared chair model could do. A mug among identical mugs matters to its owner. A remedy: accept unique matches, and keep several hypotheses when candidates look alike.
@@ 21
Closed or open set
@@ 22
With a fixed set of objects this is an optimal matching problem. If objects can be added and removed, a new, similar object is always an alternative explanation.
@@ 23
Solutions extract and match descriptors. One family puts several <strong>keypoints with descriptors</strong> on each object and solves for the 6-DoF transform from correspondences. The keypoints can be visual features or 3D descriptors such as FPFH and SHOT, which ignore appearance but describe only a local patch, so matches often need geometric verification; learned shape descriptors perform best. A second family computes a <strong>single descriptor per object</strong>. The networks are built \(\SE(3)\)-invariant, for matching across viewpoints, or \(\SE(3)\)-equivariant, for registering the matched objects. <span class="src">§15.3.2.3 · pp. 440–441</span>
@@ 24
Filling the gap: invariant and equivariant, with three points
@@ 25
Let \(f\) turn a point set \(X\) into a descriptor and \(\mathbf{T}\) be a rigid motion. \(f\) is <strong>invariant</strong> if \(f(\mathbf{T}X) = f(X)\). It is <strong>equivariant</strong> if \(f(\mathbf{T}X) = \rho(\mathbf{T})\, f(X)\) for a known action \(\rho\): the descriptor moves with the object in a predictable way.
@@ 26
Take \(X = \{(0,0),\ (2,0),\ (0,1)\}\) and the same object rotated by \(90^\circ\) and shifted by \((5,5)\): \(Y = \{(5,5),\ (5,7),\ (4,5)\}\). The sorted pairwise distances are \(\{1,\ 2,\ \sqrt5\}\) for both: an invariant descriptor, which says "same object" and not where it went. The centroid is \((\tfrac23, \tfrac13)\) for \(X\) and \((\tfrac{14}{3}, \tfrac{17}{3})\) for \(Y\), which is the first centroid rotated by \(90^\circ\) to \((-\tfrac13, \tfrac23)\) and shifted by \((5,5)\): an equivariant descriptor, which reveals part of the motion. Hence invariance for matching, equivariance for registration.

2. Change-aware SLAM: change, noise, or a wrong pose?
@@ 28
Long-term change does not wait for the next session: a robot back from the kitchen after two minutes may find the living room changed. <strong>Change-aware SLAM</strong> detects and represents such changes during online operation. <span class="src">§15.3.3 · p. 441</span>
@@ 29
This is harder than multi-session mapping. Changes can happen at any moment, so stationarity holds only over a short window, with little data to average out noise. And a pose error looks like change: with the pose estimate off by a metre, mapped surfaces seem absent although nothing moved. Localization and change detection need each other's answer. If every measurement is treated as an unchanged inlier, the registration averages true and false matches. If the whole old scene is declared changed, the open-loop estimate is trivially optimal and the map is neither complete nor consistent. <span class="src">§15.3.3 · p. 442</span>
@@ 30
Two ideas keep the problem manageable. <strong>Object-level reasoning:</strong> measurements are first summarized locally into rigid semantic objects, and localization and change decisions are made per object, a much smaller problem that is semantically consistent by construction. <strong>Local consistency:</strong> detecting change on every raw frame lets a few noisy points mark an object as changed, while cautious rules fuse different things into one corrupted model. The way out is to find stretches of data guaranteed free of change. The minimum is data tracked from frame to frame, since the scene cannot change unobserved while the robot observes it; with assumptions on the rate of change and on odometry error this extends to a sliding or active window. <span class="src">§15.3.3 · p. 442</span>
@@ 31
Filling the gap: a persistence probability
@@ 32
Several systems keep, for each object, a probability that it is still where the map says. The book gives no formula. The simplest model is a two-state Bayes filter, the mathematics of the occupancy cell of <a href="#d43">Week 8 · Day 1</a>. Let \(p\) be the probability that the object is present and \(o = p/(1-p)\) its odds. The detector fires on a present object with probability \(P_D\) (recall) and on an empty spot with probability \(P_F\). Dividing Bayes' rule for "present" by Bayes' rule for "absent":
@@ 33
The third case is Day 3's absence of evidence: no measurement, no update. Forgetting is a separate step: before each visit \(p \leftarrow s\,p\), with \(s\) the probability that the object stayed put.
@@ 34
With \(P_D = 0.8\), \(P_F = 0.05\), \(s = 1\), starting at \(p = 0.5\): one detection multiplies the odds by 16, so \(p = 16/17 = 0.94\). Each look without a detection multiplies them by \(0.2/0.95 = 0.21\): odds \(16 \to 3.37 \to 0.71 \to 0.15\), so \(p = 0.77,\ 0.41,\ 0.13\). One miss does not remove the object, because the detector misses a fifth of the time. Three in a row do.

Try it: add your own sequence of visits with the three buttons.
@@ 36
Notice: in the example, two detections lift the probability to 0.99. Three visits with the object out of view lower it only to 0.85, and only because of the 0.95 survival factor. Two looks without a detection then take it to 0.47 and 0.15, and the object is removed. Raise the recall to 0.99 and a single miss is almost conclusive. The filter is this course's illustration, not any one system's model.

@@ 38
What the book says it does
@@ 39
Panoptic Multi-TSDFs
@@ 40
A first real-time change-aware mapping system, given consistent poses. Only <strong>active submaps</strong>, tracked frame to frame, are updated. Overlapping inactive submaps are discarded whole if they disagree and merged if they agree.
@@ 41
POCD
@@ 42
Segments frames into objects and registers them against the current map, tolerating some odometry noise. A probabilistic persistence model per object is updated when the object is observed and when it should have been observed but was not.
@@ 43
NeuSE
@@ 44
Learns \(\SE(3)\)-equivariant neural object representations from partial views. Associations serve as loop-closure constraints; inconsistent or missing ones signal change.
@@ 45
POV-SLAM
@@ 46
Expectation-maximization: alternates between poses given the associations, and associations and persistence probabilities given the layout
@@ 47
Khronos
@@ 48
Creates candidate association factors between nearby objects and lets graduated non-convexity (<a href="#d35">Week 6 · Day 5</a>) pick the inliers. A first dense spatio-temporal metric-semantic SLAM method: it also estimates when each change happened.
@@ 49
Changing-SLAM
@@ 50
A first unified short- and long-term formulation, on top of ORB-SLAM. Object points are tracked frame to frame (short-term); untracked ones are associated globally to nearby objects of the same class (long-term). A persistence score lets undetected objects be forgotten.

Q1. An object's prior probability of being present is 0.5. The detector has recall 0.9 and fires on empty spots 10% of the time. The robot detects the object once, then looks again and does not detect it. What is the probability now (no forgetting)?
@@ 69
Odds start at 1. The detection multiplies them by 0.9/0.1 = 9, the miss by 0.1/0.9 = 1/9. The odds are back at 1, so p = 0.5.
