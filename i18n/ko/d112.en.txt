@@ 11
In a static scene, the flow of a pixel is fixed by its depth and the two camera poses. So flow is a measurement of pose and depth, and a factor graph can invert it. DROID-SLAM puts that inversion inside the network: a RAFT-style update operator proposes where each pixel should go and how much to trust it, and a few Gauss-Newton steps turn those proposals into pose and depth updates. Because Gauss-Newton is differentiable, the whole loop is trained on pose error.

2. Why "RAFT, then bundle adjustment" is not enough
@@ 18
Computing flow with RAFT and then minimizing (13.8) does not work particularly well, for two reasons the book gives. <span class="src">§13.3 · pp. 379–380</span>
@@ 19
The flow network was trained to get flow right, not pose. Its loss does not model what SLAM cares about.
@@ 20
The flow contains outliers, and (13.8) weights every pixel equally. You know from <a href="#d31">Week 6 · Day 1</a> what a few outliers do to least squares.
@@ 21
The fix is to make the optimization a layer of the network, a <strong>differentiable bundle adjustment (DBA)</strong> layer, so that the training loss is measured after the optimizer and its gradient reaches the network through it. And to let the network output, for every residual, a <strong>confidence weight</strong>. In the general factor-graph cost

4. Running it as a SLAM system
@@ 53
The network is trained on a fixed set of frames. Online use needs machinery around it. <span class="src">§13.3.2 · pp. 382–383</span>
@@ 54

Runs the update operator on one edge from the last keyframe to the incoming frame. If the flow revision is below a threshold, the frame is dropped.
@@ 57

@@ 58
Once enough frames are collected, connects each frame to its temporal neighbours and runs several iterations. It fails under pure rotation.
@@ 59
Adds edges for each new frame: to recent frames in both directions, and to keyframes that the induced flow shows to be highly co-visible.
@@ 60
Global optimization
@@ 61
A back-end over the full frame graph. Adds long-range edges where the induced flow between two frames is small, which closes mid-range loops.
@@ 62
The book's Figure 13.11 shows the effect of the back-end on one EuRoC sequence (V1_02_medium): the RMSE absolute trajectory error falls from 16.5 cm with the front-end only to 1.2 cm after global optimization. <span class="src">Fig. 13.11 · p. 383</span> There is no relocalization module, so a large loop with a lot of drift cannot be closed. <span class="src">p. 383</span>
@@ 63
Because the system is a factor graph, new sensors are new factors, with no retraining. <span class="src">§13.3.3 · pp. 383–384</span>
@@ 64
<strong>RGB-D:</strong> add a term that keeps each depth \(\mathbf{d}_i\) close to the sensor depth \(\bar{\mathbf{d}}_i\), with zero weight on pixels where the sensor gave no reading: \(J(\mathbf{x}) \triangleq \sum_{(i,j) \in \mathcal{G}} \| \mathbf{z}_{ij} - \mathbf{h}_{ij}(\mathbf{x}) \|^2 + \sum_i \| \bar{\mathbf{d}}_i - \mathbf{d}_i \|^2_{\boldsymbol{\Sigma}_d}\), equation (13.12).
@@ 65
<strong>Stereo:</strong> put left and right frames in the graph, add an edge between each left frame and its right partner, and hold their known relative pose fixed. Figure 13.12 shows that stereo helps considerably, partly because it removes scale drift.

@@ 86
DPVO has no loop closure beyond its window. Its successor, Deep Patch Visual SLAM (DPVS), adds global optimization, long-range loop closure through a relocalization module, and short-range loop closure by proximity. The book notes that, unlike DROID-SLAM, it keeps real-time performance on a single GPU. <span class="src">p. 386</span>
@@ 87
<strong>"DROID-SLAM predicts poses with a network."</strong> The network predicts flow revisions and confidences. Poses and depths come out of Gauss-Newton steps on (13.11).
@@ 88
<strong>"δf is the optical flow."</strong> It is a correction to the flow that the current state induces. When the state is right, the network should ask for no change.
@@ 89
<strong>"Confidence weights are a robust loss."</strong> A robust loss computes weights from residuals with a fixed formula. Here the weights are a learned function of the images and the current state, trained through the solver.
@@ 90
<strong>"Dense is always more accurate than sparse."</strong> The book reports that DPVO's sparse patches bring advantages in accuracy too. <span class="src">p. 384</span>
